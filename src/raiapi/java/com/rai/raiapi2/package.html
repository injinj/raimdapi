This package provides access to Rai Market Data middleware implementations.

Example Configuration

The api argument

The api argument is used to select which API implementation to load. The API will dynamically load the selected api implementation if the .so file is found on the LD_LIBRARY_PATH. This argument must be present in the argument list passed to the RaiApi constructor when creating the API instance.

/* checks if -api is present in args[] */
api = RaiApi.RaiOpen( null, args );
/* if first arg is not null, then it specifies the implementation */
api = RaiApi.RaiOpen( "tibrv", args );

Valid alternatives for the -api argument include sass2, capr, tibrv, sass3, and embd. Additional implementations can be added through the inclusion of the relevant rai_api_<implementation>.so file in the dynamic library path.

Standard API Implementation Values
ValueDescription
sass2TIB SASS2
caprRai Technology's Cache Protocol
tibrvTIBCO Rendezvous
sass3TIB SASS3
embdEmbedded application

Running Rai API applications

The use of different -api arguments requires different arguments to support the transport configuration parameters required. Typically these are either the specific arguments needed by the middleware or a configuration file that contains the arguments.

APIParameters

The SASS2 protocol

The SASS2 protocol is similar to the tibrv transport except that it uses an older version of the RV transport which allows initial values to arrive using the subscription request. The TIBRV transport must use a snapshot request in order to get the initial value since it does not allow an inbox reply with the subscription request.

The SASS3 protocol

The SASS3 protocol can also be used for a SASS2 subscription network as well as SASS3, but the publish network is different than SASS2. The subscription side publishes a subscription to _SASS.feed.SUB, but otherwise is compatible with SASS2. A SASS3 publisher sends data to _SASS.feed.PUB rather than the actual subject, so it must be used when the listener is active on _SASS.feed.PUB instead of _TIC.feed.> as is the case with SASS2.

The TIBCO protocol

The TIBCO protocol is similar to the SASS2 protocol excapt that the _SNAP.feed.> endpoint is used to get the initial values. It uses the tibrv library distributed with the TIBCO rvd distribution.

The CAPR protocol

The CAPR protocol uses either a TCP transport or a PGM transport and is not compatible with the above TIB protocols.
